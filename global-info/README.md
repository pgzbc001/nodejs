# global-info/

## 这个目录是什么

存放**项目级静态事实**：描述"这个项目现在是什么样的"，供 AI 了解项目全貌时使用。

与其他目录的区别：

| 目录 | 内容语义 | 维护者 | AI 写入 |
|------|---------|-------|---------|
| `project-memory/` | 团队决策与积累的知识（ADR、术语、约束） | AI 草稿 + 人工确认 | ✅ |
| `rules/` | 各 Workbench 的工程编码规范 | 人工 | ❌ |
| `global-info/` | 项目本身的事实（架构、服务、技术栈） | **人工** | ❌ |

---

## 重要：Skill 不会自动加载此目录

**所有 Skill 均不会自动读取 `global-info/` 下的文件。**

当你的任务需要 AI 了解这里的信息时，请在对话中主动 `@` 相关文件。例如：

```
/impact-analyzer @global-info/service-topology.md LION-2440 帮我做影响分析
```

或在描述任务时直接引用：

```
参考 @global-info/tech-stack.md，帮我设计这个模块的技术方案
```

---

## 应该在这里维护什么

以下是推荐放入此目录的内容类型，文件名和拆分粒度由团队自行决定：

| 内容 | 说明 | 示例文件名 |
|------|------|-----------|
| 业务概述 | 项目背景、核心业务域、目标用户 | `business-brief.md` |
| 技术栈清单 | 跨 Workbench 的技术选型事实（非规范，是现状） | `tech-stack.md` |
| 服务拓扑 | 微服务间的调用关系、依赖图 | `service-topology.md` |
| API 概览 | 跨服务 API 目录（非详细 spec，是索引） | `api-registry.md` |
| 分支管理规则 | 团队的 Git 分支策略与命名约定 | `branching-strategy.md` |
| 环境说明 | 各环境（dev/uat/prod）的地址、配置说明 | `environments.md` |

---

## 维护时机

- **项目启动时**：填入初始版本（技术栈、业务背景）
- **架构发生变化时**：例如新增微服务、调整服务间调用关系
- **团队约定变更时**：例如分支策略调整

> 该目录不纳入 AI 草稿机制，所有变更均由团队成员直接编辑。
